# ASSUMPTIONS.md - Project Design Decisions and Assumptions

1. **Partitioned Parallelism vs True Cluster**:
   - The original paper (Wu et al., 2026) utilized a dedicated Apache Spark cluster (1 master + 3 worker nodes, 172 GB RAM) with RTree indexing, Borůvka MST, and Gaussian cross-partition fusion.
   - For our lightweight, single-node implementation (B.Tech capstone target), we replace Spark and HDBSCAN with Python ProcessPool/ThreadPool multiprocessing over partitioned data slices, combined with Scikit-Learn Isolation Forest.
   - We clearly designate this as "partitioned parallel processing" rather than a distributed cluster.

2. **Datasets and Ground Truth**:
   - Primary target dataset is HDFS (LogHub HDFS_v1), where anomalies are mapped per BlockId.
   - If network or external dataset download is unavailable or times out, the self-bootstrapping system immediately falls back to a high-fidelity synthetic log generator that generates realistic HDFS block sessions and continuous streaming logs with injected anomaly scenarios (error bursts, novel templates, abnormal time gaps, frequency spikes) and a concept drift phase.
   - In synthetic evaluation, all metrics are explicitly marked as `SYNTHETIC`.

3. **Windowing Strategy**:
   - For HDFS logs, logs naturally partition by BlockId (session-based).
   - For continuous streaming logs (BGL/OpenStack/Synthetic/Custom uploads), our adaptive windowing algorithm automatically segments the log stream using arrival-rate burst ratios:
     - Burst ($\rho \ge 2.0$): 1-minute window
     - Rising ($1.3 \le \rho < 2.0$): 5-minute window
     - Baseline ($\rho < 1.3$): 10-minute window
     - Cooldown hysteresis of 2 consecutive bins before reverting to longer windows.

4. **Global vs Local Scoring**:
   - Final anomaly score formula: $S_{final} = 0.6 \times S_{local} + 0.4 \times S_{global}$.
   - $S_{local}$ is the normalized Isolation Forest anomaly score scaled via 1st and 99th train percentiles into $[0, 1]$.
   - $S_{global}$ captures global template rarity using inverse log document frequency across all partitions.

5. **Explainability and Root Cause**:
   - Severity bands: Normal $[0, 0.30)$, Low $[0.30, 0.50)$, Medium $[0.50, 0.70)$, High $[0.70, 0.90)$, Critical $[0.90, 1.00]$.
   - Root causes are generated by computing robust z-scores against normal baseline median and IQR. If an anomaly is triggered, a non-empty list of diagnostic reasons is always provided.

6. **Web Dashboard Serving**:
   - The Flask server runs on `0.0.0.0:5000` as requested.
   - For seamless viewing inside the Google AI Studio container (which routes HTTP via port 3000), Vite's proxy forwards requests from port 3000 to port 5000, and a dedicated Flask dashboard UI is served directly.
